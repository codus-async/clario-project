## 2. Complete End-to-End Academic Project Lifecycle Workflow

Clario enforces a deterministic **15-Stage Academic Project Lifecycle** within each Institution (`F-01`), Faculty (`F-09`), Department (`F-10`), Programme (`F-11`), and active Academic Session (`F-12`).

### 2.1 Prerequisite Institutional & Programme Setup
1. **Tenant & Hierarchy Provisioning:** Platform Admin creates and activates the Institution (`F-01`); Institutional Admin creates Faculty (`F-09`) $\rightarrow$ Department (`F-10`) $\rightarrow$ Programme (`F-11`) $\rightarrow$ Active Academic Session (`F-12`), registers staff/student users (`F-13`, `F-14`), maintains eligible Supervisor records (`F-16`), and appoints a Project Coordinator to the `(Programme, Academic Session)` scope (`F-15`, `BR-03`).
2. **Programme Workflow & Rubric Setup:** The appointed Project Coordinator configures the sequential Project Milestones (`F-29`), Milestone Deadlines (`F-30`), Late Penalty Policy (`F-44`), Examination Panel size (`F-47`), and Assessment & Grading Structure (`F-51`, default $30\text{ marks}$ Supervisor + $70\text{ marks}$ Examiner).

| Step # | Subscription Stage | Actors Involved | Feature IDs | Workflow Behaviour & State Transitions | Governing Rules & Integrity Controls |
|---|---|---|---|---|---|
| **Step 1** | **Plan Configuration & Tenant Onboarding** | Platform Admin $\rightarrow$ Institutional Admin | `F-01`, `F-02`, `F-03`, `F-04` | Platform Admin creates `Active` subscription plans priced in `NGN` minor units/kobo (`F-02`) and configures default grace period days (`F-04`). Institution is onboarded (`F-01`) with subscription status `Pending Payment` (or initial contracted period). | `BR-01`, `BR-28`, `BR-29` |
| **Step 2** | **Plan Selection & Payment Initiation** | Institutional Admin (`PROP-02`) $\rightarrow$ Clario Subscription Service | `F-03`, `F-67`, `F-82` | Institutional Admin updates billing profile (`F-03`), selects an `Active` plan (`F-02`) whose Max User Capacity $\ge$ current active institutional users, and clicks "Pay / Renew Subscription". System creates a `PENDING_VERIFICATION` transaction with a unique idempotent reference and exact `NGN` kobo amount (`F-67`) and opens the Payment Gateway checkout. | `BR-29`, `DAT-07`, `DAT-09`, `OD-09` |
| **Step 3** | **Payment Gateway Processing & Webhook Reception** | Payment Gateway & Webhook Sender $\rightarrow$ Clario Webhook Receiver | `F-67`, `F-68`, `F-82` | Payment Gateway processes the `NGN` payment and sends an asynchronous HTTPS webhook event (`SYS-05`) to `F-68`. `F-68` verifies the cryptographic HMAC signature (`DAT-10`) and checks the unique `Event ID` / `Transaction Reference` for duplicates (`DAT-08`, `DAT-09`). Invalid signatures are rejected (`401`); duplicate webhooks are safely ignored (`200 OK`). | `SEC-17`, `DAT-08`, `DAT-09`, `DAT-10`, `BR-NEW-04` |
| **Step 4** | **Subscription Status Synchronisation** | Clario Subscription Service | `F-03`, `F-69`, `F-70`, `F-71`, `F-72`, `F-82` | Upon verified `payment.succeeded` event (`F-68`) with matching `NGN` kobo amount:<br>• Transaction & Invoice $\rightarrow$ `Paid / Succeeded`.<br>• Institutional Subscription Status $\rightarrow$ `Active`.<br>• Validity period (`Current Period Start` & `Current Period End`) updated/extended.<br>• Any `Grace Period` or `Expired` restrictions in `F-70` are immediately lifted.<br>• Audit log (`F-82`) and confirmation notifications (`F-71`, `F-72`) dispatched.<br>*(If `payment.failed`, transaction marks `Failed`, current subscription state is preserved, and Admin is alerted to retry).* | `DAT-10`, `DAT-11`, `NFR-AUD` |
| **Step 5** | **Subscription Expiry & Grace Period Enforcement** | Scheduler & Access Control (`F-66`, `F-70`) | `F-03`, `F-04`, `F-66`, `F-70`, `F-71`, `F-72`, `F-82` | If `Current Time > Current Period End Timestamp` without a verified renewal payment:<br>• System calculates `Grace Period End = Period End + Grace Period Days` (`F-04`).<br>• Subscription Status $\rightarrow$ `Grace Period` (if Grace Days $> 0$).<br>• Warning banners and notifications (`F-71`, `F-72`) are shown to Institutional Admin, and configured Grace Period permissions (`OD-06` / `GAP-10`) apply. | `SYS-07`, `BR-NEW-01`, `OD-06` (`GAP-10`) |
| **Step 6** | **Post-Grace Period Access Restriction & Renewal Recovery** | Access Control (`F-66`, `F-70`) $\leftrightarrow$ Institutional Admin | `F-03`, `F-66`, `F-67`–`F-70`, `F-82` | If `Current Time > Grace Period End Timestamp` without renewal:<br>• Subscription Status $\rightarrow$ `Expired (Restricted)`.<br>• `F-70` enforces post-expiry restrictions (`OD-06`) across institutional users while **preserving 100% of academic data and documents** and **always preserving Institutional Admin access to `F-03`/`F-67`** to complete a renewal payment (returning to `Step 2` $\rightarrow$ `Step 4` to immediately restore `Active` status). | `SYS-07`, `DAT-11`, `NFR-BKP`, `OD-06` (`GAP-10`) |
